packets/s per queue, band 7 = highest priority (Homa's short messages and control) red underline: the queue dropped packets in the last interval

Each host port at sw1 is shaped to the bottleneck rate, then split into queues by the top 3 bits of DSCP / traffic class — where Homa writes its priority. TCP marks everything 0. Switching the policy here changes all four ports.

Homa on each host — /proc/net/homa_metrics, per second

RESENDs and timeouts are the ones to watch: under incast with the default timers they climb (the timer finding); with ×10 timers they stay low.

Resend timers

The module's defaults assume 25–100 Gbit/s. At this lab's 1 Gbit/s, data parked in a low-priority queue looks lost after 5 ms and gets re-requested; ×10 stops the spurious RESENDs (suite 07).
